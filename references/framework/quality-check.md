## 2. 일간 검사 (월~토, Step 9)

### 실행 방식

- **독립 서브에이전트**(fact-checker)를 사용하여 리포트 작성자와 분리된 시각으로 검토
- 리포트 원본과 소스 노트를 입력으로 제공
- 검사 완료 후 PASS/FAIL 판정

### 검사 항목 (8개)

#### A. 수치 정확성
- S01 이벤트의 금액, 비율, 날짜가 소스 노트 원문과 일치하는지 대조
- 전주 대비 변화율 계산 검증
- 단위 오류(B vs M, % vs %p 등) 확인

#### B. 인용 귀속
- 인물 발언이 올바른 인물에 귀속되었는지 확인
- 직접 인용과 간접 인용 구분이 정확한지 검증

#### C. 날짜·시점 정확성
- 이벤트 발생일과 리포트 기술일 일치 여부
- "이번 주", "지난달" 등 상대 시점 표현의 정확성

#### D. 논리 정합성 (핵심)
- Impact Score 부여 근거와 서술 내용의 일관성
- Power Score 방향(+/-)과 실제 분석 내용의 모순 여부
- Feedback Loop 연결의 인과 관계 타당성
- S02(시스템 역학)의 설명이 S01(이벤트)에서 도출 가능한지 검증
- S06(6개월 시사점)의 확신도 등급과 근거 강도의 적합성
- 같은 리포트 내 서로 모순되는 주장이 없는지 확인

#### E. 소스 원문 대조 (사실성 검증)
- S01 핵심 이벤트 3건의 원본 소스 URL을 실제 접근하여 소스 노트 기술과 대조
- 소스 노트가 원문의 핵심 주장을 정확히 반영하는지 확인 (왜곡·과장·누락 점검)
- 소스 다양성 점검: 단일 소스 의존 이벤트에 `[단일소스]` 태그 존재 여부
- Tier 3 단독 소스 이벤트의 Confidence가 LOW 이하인지 확인
- External Baseline(news-scanner-supplement 규칙 4) 활용 여부 점검

#### F. 섹션 간 정합성
- S07(피드백 루프) Active 목록이 S01 각 이벤트의 Feedback Loop 필드와 일치하는지 대조
- S05(전략 조정)의 판정·방향이 S04(6개월 시사점)의 분석과 논리적으로 부합하는지
- S08(내일 주목점) 3건이 S01 이벤트에서 자연스럽게 도출되는지 (무관한 주제 삽입 여부)
- S06(Map v3) Hot Layer가 S01 이벤트의 레이어 분포와 일치하는지
- S00(판단 축)이 S01 이벤트를 정확히 프레이밍하는지 (과장·축소·누락 점검)

#### G. 템플릿 준수 검사
- Quality Differentiation Rule 3조건 충족 여부:
  - (1) 각 이벤트에 피드백 루프 연결 명시 또는 "해당 없음" 명시
  - (2) 단순 뉴스 나열이 아닌 구조 변화 분석 포함
  - (3) 권력 이동 방향(누가 잃고 누가 얻는지) 명시
- Signal Type 분류(Power Shift / Lock-in Change / Standard Move / Capital Flow)가 report-template.md 정의에 부합하는지
- 각 섹션 포맷(필수 필드, 테이블 구조)이 템플릿과 일치하는지

#### H. 파생 산출물 스팟 체크
- 뉴스레터(KO/EN)의 S01 3건 이벤트 제목·핵심 수치가 리포트와 일치하는지
- 블로그 HTML의 S01 이벤트 서술이 리포트 원본과 일치하는지
- 소셜 포스트의 Lead Tweet 주장이 리포트 S01 Event 1과 일치하는지
- 변환 과정에서 수치 변형(반올림, 단위 변경 등)이 발생하지 않았는지

### 판정 기준

| 등급 | 조건 | 후속 조치 |
|------|------|-----------|
| **PASS** | 오류 0건 | 파이프라인 계속 |
| **PASS with NOTES** | 경미한 표현 개선점만 존재 | 메모 기록, 파이프라인 계속 |
| **FAIL** | 사실 오류 또는 논리 모순 1건 이상 | 리포트 수정 후 재검사 |

## 3. 심층 감사 (토요일, Step 10)

### 실행 조건

- 토요일 파이프라인(Step 1~8) 완료 후 실행
- 대상: 해당 주 월~토 6일치 리포트 전체

### 검사 항목 (9개)

#### E1. 점수 인플레이션
- 주간 Impact Score 평균 계산
- 3.5 이상이면 경고 → 과대 평가 경향 점검
- Impact 5 비율이 30% 초과 시 플래그

#### E2. 기업 편향
- 특정 기업(예: Anthropic, OpenAI, Google)이 6일간 S01 이벤트의 50% 이상을 차지하면 편향 경고
- 레이어별 기업 분포 균형 점검

#### E3. 확신 표현 위반
- 금지 표현 사용 여부: "확실히", "의심의 여지 없이", "반드시 ~할 것이다" 등
- Confidence Calibration(HIGH/MEDIUM/LOW) 태깅 누락 여부
- SPECULATIVE 급 주장에 HIGH 태깅한 경우 플래그

#### E4. 예측 정확도
- `outputs/predictions/daily/` 해당 주 파일들의 ✅/❌/⚠️ 비율 집계
- 적중률 60% 미만 시 예측 생성 기준 재검토 권고

#### E5. 레이어 커버리지
- 주간 5일(월~금) 레이어 배정(L1+L2 → L3+L4 → ... → L9+L10) 완전성 확인
- 토요일 ALL-layer에서 누락된 레이어 존재 여부

#### E6. 소스 다양성
- Tier 1/2/3 소스 사용 비율 점검
- 단일 소스 의존도 30% 초과 시 경고
- 한국어/영어 소스 균형

#### E7. S08→S01 연결률
- 각 일간 리포트의 전일 S08 "내일 주목점" 3건 중 실제로 다음날 S01에 반영된 건수 집계
- 6일 기준 전체 연결률 산출 (예: 18건 중 N건 반영 = N%)
- 연결률 40% 미만 시 경고 — S08이 형식적 예고에 그치고 있다는 의미
- 미반영 사유 분류: (a) 해당 뉴스 부재, (b) 발생했으나 선택 탈락, (c) S08 작성 시 방향 오판

#### E8. 피드백 루프 인플레이션
- 6일간 S07에서 Active로 표시된 루프 수의 일별 합계·평균 산출
- 일평균 Active 루프 4개 이상 시 경고 — 6개 루프 중 거의 전부가 매일 Active이면 변별력 상실
- 동일 루프가 6일 연속 Active이면서 근거가 실질적으로 갱신되지 않은 경우 플래그 (관성적 Active 유지)
- Dormant 루프가 1주간 0개이면 재검토 권고

#### E9. 한영 일관성
- S01 3건의 KO Summary와 EN Summary가 동일한 핵심 주장·수치를 포함하는지 대조
- S04 한국어/영어 시사점이 동일한 결론을 전달하는지 확인
- 한쪽에만 있는 수치, 주장, 엔티티 언급이 있으면 불일치 플래그
- 불일치가 "현지화 차이"인지 "실수"인지 분류

### 블로그 소급 수정

심층 감사에서 사실 오류가 발견된 경우:
- **블로그 HTML**: 해당 포스트 수정 + 하단에 `[수정: YYYY-MM-DD] 내용` 주석 추가
- **뉴스레터**: 소급 수정하지 않음 (이미 발송된 것으로 간주)

## 4. 주간 검사 (일요일) — 발행 전 감사

### 실행 시점 및 순서

일요일 파이프라인은 일간(월~토)과 다르게, **감사를 리포트 발행 전에** 실행한다.
일간 리포트는 감사 후 피드백이 다음 주에 반영되지만, 주간 리포트는 발행 후 수정까지 1주일의 공백이 생기므로 사전 검증이 필수다.

**일요일 파이프라인 순서:**
1. 주간 종합 리포트 생성 (Step 2에 해당)
2. **주간 품질 검사 실행 (A~H + E1~E9)** ← 발행 전
3. FAIL 시 리포트 수정 → 재검사 → PASS 확인
4. PASS 후 뉴스레터·블로그·소셜·아카이브 발행 (Step 3~8)

> 핵심: 일간은 Step 8 → Step 9(감사) 순서지만, 일요일은 Step 2 → 감사 → Step 3~8 순서다.

### 검사 범위

주간 리포트 1건에 대해 **일간 검사(A~H) + 심층 감사(E1~E9)** 모두 실행.

### 산출물: `YYYY-WNN_weekly-audit.md`

```markdown
# Weekly Audit — {YYYY}-W{NN}

## 검사 대상
- 주간 리포트: {filename}

## 판정: {PASS / PASS with NOTES / FAIL}

## 일간 검사 (A~H)
[위 일간 검사와 동일 포맷 — A~H 전 항목]

## 심층 감사 (E1~E9)
[위 심층 감사와 동일 포맷, 대상은 주간 리포트 단일 문서]

## 피드백 → 다음 주 적용 사항
- [개선 권고 목록]
```

---

## 5. 피드백 반영 규칙

1. 토요일 심층 감사와 일요일 주간 검사에서 도출된 피드백은 **다음 주 월요일**부터 적용
2. 피드백 적용 확인은 다음 주 토요일 심층 감사 시 점검
3. 반복 발생 피드백(3주 연속)은 `references/` 파일 업데이트로 구조화

## 6. 서브에이전트 실행 사양

### 일간 검사용 fact-checker 호출

```
Agent(
  subagent_type: "ai-power-atlas:fact-checker",
  prompt: "다음 리포트의 품질 검사를 수행하라.
  - 리포트: {report path}
  - 소스 노트: {source-notes path}
  - 뉴스레터: {newsletter KO path}, {newsletter EN path}
  - 블로그: {blog KO path}, {blog EN path}
  - 소셜: {social path}
  - 참조: references/report-template.md (Quality Differentiation Rule, Signal Type 정의)

  검사 항목 8개:
  A. 수치 정확성 — 소스 노트 vs 리포트 수치 대조
  B. 인용 귀속 — 인물 발언의 정확한 귀속
  C. 날짜·시점 — 이벤트 발생일, 상대 시점 표현
  D. 논리 정합성 — Score 근거, Power Score 방향, 루프 인과, 섹션 간 모순
  E. 소스 원문 대조 — S01 3건 원본 URL 접근 → 소스 노트 기술 정확성
  F. 섹션 간 정합성 — S07↔S01 루프 일치, S05↔S04 부합, S08↔S01 연결, S06 Hot Layer 일치, S00 프레이밍 정확성
  G. 템플릿 준수 — Quality Differentiation Rule 3조건, Signal Type 분류 정확성, 포맷 일치
  H. 파생 산출물 스팟 체크 — 뉴스레터/블로그/소셜의 S01 수치·주장이 리포트 원본과 일치

  각 항목별 결과(이상 없음 / 발견 사항 상세)와 최종 PASS/PASS with NOTES/FAIL 판정을 반환하라."
)
```

### 심층 감사는 메인 에이전트가 직접 수행
